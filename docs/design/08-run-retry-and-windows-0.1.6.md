## 修复结果

提交已被服务器接受，但响应丢失时，浏览器重试会保留同一个请求标识。服务器在同一运行上下文内复用原任务，只保留一条用户消息，并且只有首次创建者启动执行。请求内容不同却复用标识时返回冲突；确认后的新提交使用新标识。

请求标识、任务和第一条事件一起发布；发布后立即交给独立执行任务，避免请求断开留下未启动的任务。模型启动或执行失败会补齐结束事件。事件消费与执行同时进行，错误消息及其后的结束事件都能保留，事件广播顺序与日志顺序一致。最终状态在结束事件写入后才对恢复连接的客户端可见。

WebUI 恢复成功、失败、取消或 `paused` 快照后会关闭旧连接；迟到的请求、快照及旧连接回调不会覆盖当前任务。运行中的连接错误仍作为连接问题显示。事件地址已修正为实际可用的 `/api/v1/runs/{id}/events`。

`Idempotency-Key` 允许一个 1–128 字节的可见 ASCII 值。错误内容不回显请求标识或提示词。去重记录与服务器内存中的任务注册表同寿命，**不跨程序重启保留**。详细接口约定见 [协议说明](../../packages/protokoll/README.md#run-submission-retries)。

完整验证还发现 Windows 权限修复子进程继承了 PowerShell 7 的模块路径，导致 Windows PowerShell 无法加载 `Get-Acl`。现在仅清除该子进程的 `PSModulePath`，使其建立自身路径，保留原有私有文件检查和授权修复。该兼容情形也见 [Microsoft 的模块路径说明](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_psmodulepath?view=powershell-7.6)。

## 网络与界面验收

新增 3 项实际回环 HTTP/WebSocket 测试：16 个并发相同请求只创建一条首轮消息；直接使用服务器返回的事件地址成功升级并重放最终日志；从已读序号重连不重复首条事件；读取成功响应状态行后主动断开，重试仍恢复同一个失败任务；冲突、非法或重复请求标识的错误响应不泄露提交内容。另有注册表并发和实时事件测试验证执行归属、首次发布及广播顺序。

浏览器验收直接运行本次安装包同一份生产 `apps/web/dist`。临时回环服务明确显示“提交恢复验收”和“UI fixture / 本地模拟”，不使用实际模型、密钥或用户会话：

1. 输入带首尾空白和换行的草稿；首次请求已接收，服务主动丢弃响应。界面显示连接错误，原始草稿逐字保留，仍可再次发送。
2. 按 Enter 重试。两次请求的标识和任务 ID 完全相同，服务只创建一个任务，界面恢复完成结果及结束事件。
3. 确认完成后再次发送相同内容。使用新标识和新任务 ID，验证新的用户提交不会被旧标识阻挡。

浏览器控制台错误列表为空；界面中的首次 `Failed to fetch` 是主动丢弃响应的预期结果。临时服务和验收标签页在完成后关闭。

已实际启动安装后的原生程序，确认主界面及本地事件连接正常，保存真实深色截图。模型未配置时显示“设置模型”，不会自动发起推理。**本轮没有调用外部模型 API。**

原生启动检查发现 3 个旧命令行测试未指定临时 home，两次完整验证留下了 6 条 `hello default/run/stdin` Mock 会话。现已为这些测试设置独立临时 home，并在成功后清理。仅包含本轮这 6 条记录、创建于本轮验证期间的日志已核验并移至任务工作目录的可恢复备份 `cli-mock-session-log-backup.jsonl`；重新启动后的真实界面确认默认历史为空。
